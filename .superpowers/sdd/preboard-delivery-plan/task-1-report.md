# Task 1 report

- Broker supports a bounded signed millimetre trace read from a regular file before worker launch. Replay uses the actual worker IPC and stamps both submissions from one sample. Live staging uses the same history. Sensor rows identify missing truth separately from input.
- The workbench optionally observes stdin JSONL through a finite independent spool and SSH tail. The read-only board endpoint bounds frame size, retained rows and simultaneous writers. It reports upstream disconnect, run identity, skipped malformed and oversized frames, sequence gaps and evicted rows. The chart breaks at missing sequences.
- The standalone LED consumer provides dry-run output and an absolute-path executable adapter for BSP GPIO. Rollback hold is measured in sample sequence slots. The QNX 8 AArch64 SDK installation contains Python 3.13 and `hw/i2c.h`. GPIO pin mapping, I²C capture, target runtime packaging and timing need board evidence. #4 retains ownership of producer-side isolation from slow local storage.
- Operator instructions are in `docs/preboard-pipeline.md`. `preboard-pipeline` CTest covers shared worker input, invalid/short/overlong/extra traces, FIFO rejection, relay bounds and recovery, dropped and evicted rows, upstream EOF, abandoned and deterministically stalled HTTP observers, missing or invalid truth fields, and LED replay/reset/error handling. The LED accepts the broker summary after a terminal failure while keeping the LED off. Local HTTP run timeout scales with the configured sample count and period. The documented SSH procedure closes stdin on disconnect so the workbench shows EOF.
