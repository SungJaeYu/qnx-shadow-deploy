# Native QNX execution evidence

Captured on 2026-11-23 from the existing image and binaries, with runtime source at `af72fba`. See [verification](../../verification.md#native-qnx-execution-2026-11-23) for results and limits. No SDK executable, image, license or credential is included here.

- `environment.json`: exact host/emulator configuration, reused artifact hashes, runtime build-ID comparisons and export checksums.
- `results.json`: output of `tools/verify_qnx_logs.py` against the exported files.
- `shadow-validation/`: original guest files, transferred as tar/base64 over the serial console. JSONL and stderr bytes were not rewritten.
- `serial-console.log`: exact serial bytes from boot through the first archive export command, excluding the base64 archive payload.
- `serial-timeout-console.log` and `serial-timeout-observed-console.log`: exact serial segments around the two additional diagnostic runs, excluding archive payloads.
- `host-ctest.log`: fresh host test output, including the socket-permission failure during HTTP setup.
- `negative-controls.json`: verifier checks against temporary corrupted copies; the original evidence was unchanged.
- `sha256.json`: file sizes and SHA-256 digests for the other files in this evidence directory.

The full raw serial capture, including base64 transport and VM exit, and the three decoded tar archives are retained locally under ignored `artifacts/native-validation/`. The checked-in serial segments omit only separately exported archive transport; their carriage returns and terminal control bytes are preserved.

## Results

Policy and staging passed on QNX. Eleven functional scenarios at 100/75 ms reached their expected outcomes; the three intentional output-stop scenarios returned 3. Default 20/10 ms scenarios retain five early deadline failures. Default and functional live attachment, cancellation/retry and six replay rejections followed by generation-seven promotion all retained baseline PID continuity. All 30 traces identify `qnx-native-ipc`.

The two lifecycle traces and connection/process snapshots were generated by `tools/qnx_lifecycle_checks.sh`. The snapshot sets show candidate connection/pipe retirement and no child left after broker exit. `executed-lifecycle.sh` is the exact guest-executed script; its POSIX checksum is `2413034024`, length 2732 bytes.

The first timeout diagnostic used `executed-timeout.sh` (checksum `4212340202`, length 1496 bytes). Both runs rejected the candidate as expected, but the single `timeout-send.threads` snapshot did not capture a blocking state. The name records the original hypothesis, not a verified SEND result. `executed-timeout-observed.sh`, matching the final `tools/qnx_timeout_checks.sh`, polls the second acquisition and observes REPLY in both the stopped-receiver and delayed-reply probes. Isolated SEND timeout behavior remains open. Initial exit and final-process records are preserved as `initial-timeout-*`; later records append the new executions.

The guest started as root with default scheduling. No hardware timing, WCET, production security policy, resource isolation, exhaustive timeout race coverage or full 8.0.6 release-set claim is made. Five runtime build IDs match SDK packages; the inventory is in [qnx-sdk-audit.json](../qnx-sdk-audit.json).

## Export integrity

Before QEMU exited, guest tar files were streamed as base64 and decoded on the host. POSIX `cksum` and length matched for each archive:

| Export | POSIX checksum | Bytes |
| --- | --- | --- |
| Initial scenarios and lifecycle | 2791382996 | 836096 |
| Initial timeout probes and runtime metadata | 4254802337 | 18944 |
| Polling-based timeout probes | 1964786645 | 18432 |

The original disk and executable SHA-256 values were checked again after VM exit and were unchanged. Base64 transport preserved files despite the serial console's CR/LF conversion. An initial long here-document transfer was interrupted after truncation; the actual executed scripts were transferred in short base64 lines, decoded, and checked before execution.

## Recheck on any host with Python 3.9+


The verifier reads target recordings; it does not execute QNX binaries on the host or convert the default-budget failures into successful timing results. For a new guest session, run the original binaries, preserve exit codes and stderr, execute the two guest scripts, and export the files before quitting `-snapshot`.
